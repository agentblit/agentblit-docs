Users can add a **custom HTTP connector** in AgentBlit by exposing REST endpoints on a publicly accessible URL, then registering that URL in the AgentBlit console.

## Overview

A custom HTTP connector lets your backend expose tools that agents can discover and invoke. AgentBlit calls your service to list tools, execute them, and optionally load interactive UI. Authentication uses an **API key** that the user pastes when connecting the tool to an agent.

The flow has two parts:

1. **Build** — Implement the required endpoints (and any optional ones you need), then deploy them on a public HTTPS URL. Provide a dashboard where users configure entities and mint API keys.
2. **Register** — Add the connector URL (and optional dashboard URL) in the AgentBlit console, then attach it to an agent by pasting the API key.

AgentBlit always appends fixed paths under your base URL:

| Endpoint | Method | Required | Auth |
| --- | --- | --- | --- |
| `/api/1.0/tools/list` | `GET` | Yes | `X-API-Key` |
| `/api/1.0/tools/call` | `POST` | Yes | `X-API-Key` |
| `/api/1.0/resources/read` | `GET` | Only if tools declare UI | `X-API-Key` |

The [appointment-tool](https://github.com/agentblit/appointment-tool) project is a full reference implementation of this contract.

---

## API key auth

AgentBlit stores the connector API key (encrypted) per agent connection and sends it on all runtime calls:

```http
X-API-Key: <connector-api-key>
```

| Endpoint | Header |
| --- | --- |
| `tools/list` | Required (also used to verify the key on connect/reconnect) |
| `tools/call` | Required |
| `resources/read` | Required |

Issue API keys from your connector dashboard. Use the key as your tenancy key (config, bookings, etc.). Return HTTP `401` when the key is missing or invalid.

### API types

Use these types in your connector service. `parameters` is a [JSON Schema](https://json-schema.org/) object and varies per tool. Expand a language below to copy the types.

```ts
/** GET /api/1.0/tools/list */
export interface ListToolsResponse {
  tools: ToolDefinition[];
}

export type ToolPermissionMode =
  | 'always_allow'
  | 'needs_approval'
  | 'blocked';

export interface ToolDefinition {
  type: 'function';
  function: FunctionDefinition;
  /** How AgentBlit should treat the tool before running it */
  permission_mode?: ToolPermissionMode;
  /** MCP Apps UI metadata — pair with GET /api/1.0/resources/read */
  _meta?: {
    ui?: {
      resourceUri: string;
      visibility?: Array<'model' | 'app'>;
    };
  };
}

export interface FunctionDefinition {
  name: string;
  description: string;
  /** JSON Schema for tool arguments */
  parameters: Record<string, unknown>;
}

/** POST /api/1.0/tools/call — request body */
export interface CallToolsRequest {
  tool_calls: ToolCall[];
  /** Present when retrying after an elicitation_required response */
  elicitation_result?: {
    action: 'accept' | 'decline' | 'cancel';
    content?: Record<string, string | number | boolean | string[]>;
  };
}

export interface ToolCall {
  id: string;
  type: 'function';
  function: ToolCallFunction;
}

export interface ToolCallFunction {
  name: string;
  /** JSON-encoded arguments matching the tool's parameter schema */
  arguments: string;
}

/** POST /api/1.0/tools/call — response body */
export interface CallToolsResponse {
  results: ToolCallResult[];
}

export interface ToolCallResult {
  tool_call_id: string;
  result?: ToolResult;
  /** Soft failure for this row (HTTP 200) */
  error?: string;
  /** Pause and ask the user for input, then retry with elicitation_result */
  elicitation_required?: {
    message: string;
    requestedSchema?: Record<string, unknown>;
  };
}

export interface ToolResult {
  content?: ToolResultContent[];
  /** Alternative to content[] — opaque JSON for the model */
  structuredContent?: unknown;
}

export interface ToolResultContent {
  type: 'text';
  text: string;
}

/** GET /api/1.0/resources/read?uri=… */
export interface ResourcesReadResponse {
  contents: UiResourceContent[];
}

export interface UiResourceContent {
  uri: string;
  mimeType: 'text/html;profile=mcp-app';
  text: string;
  _meta?: {
    ui?: {
      prefersBorder?: boolean;
      csp?: {
        connectDomains?: string[];
        resourceDomains?: string[];
      };
    };
  };
}
```

Parse `arguments` when handling a call:

```ts
function parseToolArguments<T>(toolCall: ToolCall): T {
  return JSON.parse(toolCall.function.arguments) as T;
}

// Example: check_available_slots arguments
interface CheckAvailableSlotsArgs {
  entity_id: string;
  date_from: string;
  date_to: string;
  timezone: string;
}

const args = parseToolArguments<CheckAvailableSlotsArgs>(toolCall);
```

```go
package connector

import "encoding/json"

const (
	ToolTypeFunction = "function"
	ContentTypeText  = "text"
	MimeTypeMcpApp   = "text/html;profile=mcp-app"
)

// ListToolsResponse is the body for GET /api/1.0/tools/list.
type ListToolsResponse struct {
	Tools []ToolDefinition `json:"tools"`
}

type ToolDefinition struct {
	Type           string             `json:"type"`
	Function       FunctionDefinition `json:"function"`
	PermissionMode string             `json:"permission_mode,omitempty"` // always_allow | needs_approval | blocked
	Meta           *ToolMeta          `json:"_meta,omitempty"`
}

type ToolMeta struct {
	UI *ToolUIMeta `json:"ui,omitempty"`
}

type ToolUIMeta struct {
	ResourceURI string   `json:"resourceUri"`
	Visibility  []string `json:"visibility,omitempty"` // model | app
}

type FunctionDefinition struct {
	Name        string          `json:"name"`
	Description string          `json:"description"`
	Parameters  json.RawMessage `json:"parameters"` // JSON Schema object
}

// CallToolsRequest is the body for POST /api/1.0/tools/call.
type CallToolsRequest struct {
	ToolCalls          []ToolCall          `json:"tool_calls"`
	ElicitationResult  *ElicitationResult  `json:"elicitation_result,omitempty"`
}

type ToolCall struct {
	ID       string           `json:"id"`
	Type     string           `json:"type"`
	Function ToolCallFunction `json:"function"`
}

type ToolCallFunction struct {
	Name      string `json:"name"`
	Arguments string `json:"arguments"` // JSON-encoded arguments
}

type ElicitationResult struct {
	Action  string         `json:"action"` // accept | decline | cancel
	Content map[string]any `json:"content,omitempty"`
}

// CallToolsResponse is the body for POST /api/1.0/tools/call.
type CallToolsResponse struct {
	Results []ToolCallResult `json:"results"`
}

type ToolCallResult struct {
	ToolCallID           string                `json:"tool_call_id"`
	Result               *ToolResult           `json:"result,omitempty"`
	Error                string                `json:"error,omitempty"`
	ElicitationRequired  *ElicitationRequired  `json:"elicitation_required,omitempty"`
}

type ToolResult struct {
	Content           []ToolResultContent `json:"content,omitempty"`
	StructuredContent any                 `json:"structuredContent,omitempty"`
}

type ToolResultContent struct {
	Type string `json:"type"`
	Text string `json:"text"`
}

type ElicitationRequired struct {
	Message         string          `json:"message"`
	RequestedSchema json.RawMessage `json:"requestedSchema,omitempty"`
}

// ResourcesReadResponse is the body for GET /api/1.0/resources/read.
type ResourcesReadResponse struct {
	Contents []UiResourceContent `json:"contents"`
}

type UiResourceContent struct {
	URI      string          `json:"uri"`
	MimeType string          `json:"mimeType"`
	Text     string          `json:"text"`
	Meta     json.RawMessage `json:"_meta,omitempty"`
}
```

Parse `Arguments` when handling a call:

```go
type CheckAvailableSlotsArgs struct {
	EntityID string `json:"entity_id"`
	DateFrom string `json:"date_from"`
	DateTo   string `json:"date_to"`
	Timezone string `json:"timezone"`
}

func parseToolArguments[T any](tc ToolCall) (T, error) {
	var args T
	if err := json.Unmarshal([]byte(tc.Function.Arguments), &args); err != nil {
		return args, err
	}
	return args, nil
}
```

### 1. List tools

**`GET /api/1.0/tools/list`**

Returns the list of tools and their definitions (OpenAI-style function schemas). Requires `X-API-Key`. AgentBlit calls this endpoint when connecting or reconnecting to validate the key and refresh the tool catalog.

```bash
curl --location 'https://your-service.example.com/api/1.0/tools/list' \
  --header 'X-API-Key: apt_your_connector_api_key'
```

**Response**

```json
{
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "list_entities",
        "description": "List all configured bookable entities for this agent.",
        "parameters": {
          "type": "object",
          "properties": {}
        }
      },
      "permission_mode": "always_allow"
    },
    {
      "type": "function",
      "function": {
        "name": "check_available_slots",
        "description": "Show available appointment times for one entity.",
        "parameters": {
          "type": "object",
          "properties": {
            "entity_id": {
              "type": "string",
              "description": "UUID of the entity to check"
            },
            "date_from": {
              "type": "string",
              "description": "Start date (YYYY-MM-DD) in the chat user's timezone"
            },
            "date_to": {

```

Each entry in `tools` must include:

- `type`: `"function"`
- `function.name`: Unique tool name used when calling the tool
- `function.description`: What the tool does (shown to the model)
- `function.parameters`: JSON Schema for the tool’s arguments

Optional fields:

| Field | Description |
| --- | --- |
| `permission_mode` | `always_allow` (default), `needs_approval` (user must confirm), or `blocked` |
| `_meta.ui.resourceUri` | `ui://…` URI served by `/api/1.0/resources/read` |
| `_meta.ui.visibility` | `["model","app"]` (default), `["model"]`, or `["app"]` |

### 2. Call tools

**`POST /api/1.0/tools/call`**

Executes one or more tool calls and returns results keyed by `tool_call_id`.

**Request**

```bash
curl --location 'https://your-service.example.com/api/1.0/tools/call' \
  --header 'Content-Type: application/json' \
  --header 'X-API-Key: apt_your_connector_api_key' \
  --data '{
    "tool_calls": [
      {
        "id": "call_IWHXuqijtAyAj30UBMSfjlGU",
        "type": "function",
        "function": {
          "name": "check_available_slots",
          "arguments": "{\"entity_id\":\"22222222-2222-2222-2222-222222222222\",\"date_from\":\"2026-07-26\",\"date_to\":\"2026-07-28\",\"timezone\":\"America/New_York\"}"
        }
      }
    ]
  }'
```

| Field | Description |
| --- | --- |
| `tool_calls` | Array of tool invocations from the agent |
| `tool_calls[].id` | Correlates with `tool_call_id` in the response |
| `tool_calls[].function.name` | Must match a name from `/tools/list` |
| `tool_calls[].function.arguments` | JSON string of arguments matching the tool’s parameter schema |
| `elicitation_result` | Optional; present when AgentBlit retries after `elicitation_required` |

**Success response**

```json
{
  "results": [
    {
      "tool_call_id": "call_IWHXuqijtAyAj30UBMSfjlGU",
      "result": {
        "content": [
          {
            "type": "text",
            "text": "{\"ok\":true,\"entity_id\":\"22222222-2222-2222-2222-222222222222\",\"slots\":[{\"start\":\"2026-07-26T14:00:00-04:00\",\"end\":\"2026-07-26T14:30:00-04:00\"}]}"
          }
        ]
      }
    }
  ]
}
```

Each item in `results` may include one of:

| Field | Description |
| --- | --- |
| `result.content` | Array of `{ type: "text", text }` blocks; put JSON payloads in `text` as a string |
| `result.structuredContent` | Alternative opaque JSON result |
| `error` | Soft failure for this row (still HTTP 200) |
| `elicitation_required` | Ask the user for input; AgentBlit retries with `elicitation_result` |

Return HTTP `400` for invalid bodies and `401` when the API key is missing or invalid. Prefer `error` on a result row for tool-level failures so other calls in the batch can still succeed.

### 3. UI resources (optional)

If a tool declares `_meta.ui.resourceUri`, implement:

**`GET /api/1.0/resources/read?uri=…`**

Requires `X-API-Key`.

```bash
curl --location 'https://your-service.example.com/api/1.0/resources/read?uri=ui%3A%2F%2Fappointment%2Fcheck-slots' \
  --header 'X-API-Key: apt_your_connector_api_key'
```

**Response**

```json
{
  "contents": [
    {
      "uri": "ui://appointment/check-slots",
      "mimeType": "text/html;profile=mcp-app",
      "text": "<!DOCTYPE html>…",
      "_meta": {
        "ui": {
          "prefersBorder": true,
          "csp": {
            "connectDomains": [],
            "resourceDomains": []
          }
        }
      }
    }
  ]
}
```

Requirements:

- `uri` must start with `ui://`
- `mimeType` must be exactly `text/html;profile=mcp-app`
- `text` is the full HTML document rendered in an iframe

The HTML should use the MCP Apps bridge (`postMessage` JSON-RPC) so the iframe can call tools through AgentBlit (`tools/call`) instead of calling your connector directly. Keep `connectDomains` empty unless the app must fetch external origins.

### 4. Deploy on a public URL

Host the endpoints on an **HTTPS URL** reachable from the internet (for example `https://your-service.example.com`). AgentBlit will call:

- `GET https://your-service.example.com/api/1.0/tools/list`
- `POST https://your-service.example.com/api/1.0/tools/call`
- and `resources/read` if your tools declare UI

When you add a custom HTTP connector, AgentBlit probes `tools/list` (without an API key) to confirm the URL is reachable — a `401` response is treated as success because the endpoint exists. Use the **base URL** of your deployment when registering (no path suffix). Optionally set a **dashboard URL** so users can open your UI (in a new tab) to mint an API key.

On **connect** or **reconnect**, AgentBlit calls `tools/list` **with** the pasted API key. If the key is invalid, connection fails.

## Add a custom connector in AgentBlit

After your APIs are live:

1. **Create an account** in the [AgentBlit console](https://console.agentblit.com).
2. **Create an agent** for your use case.
3. Open **Connectors** → **Add custom connector**.
4. Choose **Custom HTTP connector**, enter your service’s public base URL, and optionally a dashboard URL.
5. On the agent page, click **Add tool**, select your connector, paste the API key from your dashboard, and connect. AgentBlit verifies the key via `tools/list` and stores the discovered tools.

AgentBlit discovers tools from your list endpoint and invokes them through the call endpoint when the agent needs them.
